# Futures Radar · AI 期货市场分析

面向国际期货（能源、金属、农产品、金融期货）的 AI 分析网站，全部运行在 Cloudflare 上。网站有两个视图：

- **品种**：12 个期货品种的主力合约行情、期限结构和每日 AI 行情解读（利多/利空归因）。
- **事件**：自动采集新闻，把报道归并成事件，分析每个事件对期货的影响（方向、传导链、时间线、严重性），再用主力合约的实际行情校准。

> 只做分析和归因，不提供交易信号、目标价或仓位建议。页面上都有免责声明。

```
新闻 RSS / GDELT ─► 聚类成事件 ─► 分诊 ─► 深度分析（对各期货品种的影响）─► 用主力合约行情校准 ─┐
                                                                                            ├─► 前端（品种 / 事件）
Yahoo 期货合约日线 ─► 期限结构 + 识别主力合约 ─► 主力小时线 ─► 行情快照 ─► 每日 AI 解读 ───────┘
```

## 品种

| 品类 | 品种（代码 / 交易所） |
|---|---|
| 能源 | WTI原油 CL、布伦特原油 BZ、天然气 NG（NYMEX） |
| 金属 | 黄金 GC、白银 SI、铜 HG（COMEX） |
| 农产品 | 大豆 ZS、玉米 ZC、小麦 ZW（CBOT） |
| 金融期货 | 标普500 ES、纳指100 NQ（CME），美国10年期国债 ZN（CBOT） |

品种定义在 `src/instruments.js`，包括交割月份周期和单位。增减品种只需改这个文件。

**主力合约与期限结构**（`src/contracts.js`）：每天美盘收盘后（UTC 22 点），按各品种的交割月周期拼出接下来的合约代码（例如 `CLZ26.NYM`），取每个合约最近一个月的日线：
- 最近 7 天没有成交的合约视为已到期，跳过；保留最多 6 个合约，组成期限结构。
- 主力合约 = 最近 3 个有效合约中，近 3 日平均成交量最大的那个。
- 计算近月对次月价差、升水/贴水、多头展期年化收益和曲线斜率。
- 主力换月时，自动回填新主力 3 个月的小时线。

**为什么按合约存行情**：连续合约（`CL=F`）在换月时会出现价差跳空。如果拿它算事件反应，会把换月误判为“暴涨暴跌”。现在 `prices` 表按合约分开存，计算市场反应时只用同一个合约的数据（测试里专门验证了这一点）。波动率改用中位数绝对偏差（MAD），少数跳空不会把基线抬高。

**每日 AI 行情解读**（`src/futures.js`，UTC 23 点生成）：
- 系统先算好所有数字：1/5/20 日涨跌、20 日年化波动率、3 个月区间位置、20/60 日均线、期限结构，以及近 7 天与该品种相关的已分析事件和模型过往命中率。
- 模型只负责归因：给出标题、摘要、走势描述、3–6 条利多/利空因素（标注依据是事件、期限结构、价格行为还是宏观/季节性）、期限结构解读、上下两个方向的风险，以及接下来要关注的数据。
- 引用的事件编号必须真实存在，否则会被删掉。提示词明确禁止给出买卖、目标价或仓位建议。
- 行情快照每小时更新一次。前端只读 12 行快照，不直接扫描行情表。

## 设计要点

- **分数由代码计算**：模型给 7 个维度各打 0–5 分并写理由（军事升级、市场冲击、供需冲击、系统性传导、地理范围、持续性、升级势头），总分按 `src/rubric.js` 里的权重算出。针对期货，“人员影响”换成了“供需冲击”。
- **防止幻觉**：每条结论必须引用信源编号 `[S1]`。没有有效信源的时间线条目直接丢弃。原文引句逐字核对，前端显示“✓ 已核对 / ⚠ 未找到”。
- **品类筛选**：事件受影响的品类由分析里列出的期货品种自动推出，前端可以按 能源/金属/农产品/金融期货 筛选。
- **严重性历史**：每次分析和市场校准都记一笔，前端画出趋势线。
- **信源**：国际时政、防务、财经 RSS，美联储，EIA（Today in Energy、新闻稿），以及两条 GDELT 查询（大宗商品、宏观与地缘）。
- **版权**：正文只用于分析，前端只显示中文摘要和原文链接，正文 30 天后清除。

## 市场校准是怎么算的

1. **行情**：12 个品种的主力合约小时线（识别出主力之前用连续合约）。
2. **锚点**：事件首篇报道时间往前推 2 小时（`MARKET_PRE_HOURS`），因为市场往往比新闻先动。
3. **选合约**：在锚点前 30 天到后 72 小时内，选 K 线最多的那个合约，保证基线和事件窗口来自同一合约。
4. **异动幅度**：分别看锚点后 4、24、72 小时的价格变化，除以“事件前 30 天的稳健小时波动率 × √K线数”，得到 z 值，也就是“相当于平时几倍的波动”。
5. **实测分（0–5）**：最大 |z| 小于 1 记 0 分，1–2 记 1 分，2–3 记 2 分，3–4.5 记 3 分，4.5–7 记 4 分，7 以上记 5 分。3 个以上品种同时 ≥2σ 时至少给 3 分。
6. **融合**：校准分 = 模型分 ×(1−w) + 实测分 × w。模型点名了对应品种时 w 最高 0.6，否则用核心品种（布伦特、黄金、铜、标普、10年美债）兜底，w 最高 0.3。24 小时窗口走完才拿满权重；72 小时后定稿。
7. **方向核对**：模型对每个品种的“上涨/下跌/波动加剧”预测逐一和实际对比，|z|<1 记为不显著。“模型校准”页按品种汇总命中率。

**行情数据源**：Yahoo Finance 的 v8 chart 接口（免 key，非官方，可能限流或改版）。Twelve Data 只作为黄金和布伦特的备用源，而且给的是现货价，单独记为 `spot`，不和期货合约混算。

## 套餐与成本

**需要 Workers Paid（$5/月）。** 免费版有两个硬限制，这个项目一定会超出：每次调用只有 10ms CPU，每次调用最多 50 次 D1 查询。一批 10 篇文章的聚类、一次全量市场校准都会超过。付费版是 30 秒 CPU（可调）和 1000 次查询，D1、Queues、Vectorize 的额度也都够用。

## 模型路由（多家免费模型 + 可选 Claude）

所有 LLM 调用都经过 `src/llm.js` 的路由：按调用链顺序尝试，某一家限流、报错或输出不合格时自动换下一家。没配 key 的提供商会被跳过。

| 提供商 | 默认模型 | 免费额度（2026-11 核对，以各家控制台为准） | 路由里的保护 |
|---|---|---|---|
| Workers AI | `@cf/qwen/qwen3-30b-a3b-fp8` | 10,000 Neurons/天 | 估算 Neurons，用到 8,000 就停 |
| Groq（快） | `llama-3.1-8b-instant` | 14,400 次/天、每分钟 6K token | 提示超过 4.5K token 不发 |
| Groq | `llama-3.3-70b-versatile` | 1,000 次/天、10 万 token/天、每分钟 12K token | 每天 9.5 万 token 封顶；提示超过 9K 不发 |
| 智谱 | `glm-4.7-flash` | 免费，按并发限流 | 限流后按 Retry-After 冷却 |
| Ollama Cloud | `deepseek-v4-flash` | 免费版有用量上限 | 默认每天 300 次（可调） |
| OpenCode Zen | `deepseek-v4-flash-free` | 免费模型 | 默认每天 200 次（可调） |
| OpenRouter | `openrouter/free` | 50 次/天、每分钟 20 次 | 每天 45 次封顶，不做修复重试 |
| Claude（可选，付费） | Haiku 5.5 / Sonnet 5.5 | — | 受 `DAILY_BUDGET_USD` 约束 |

**当前部署调用顺序**（见 `wrangler.toml`）：所有任务都优先走 Workers AI 的 Qwen3-30B，每天最多 100 次；Qwen 达到调用数或 Neurons 保护上限、故障或输出不合格时，才依次尝试备用免费模型。
- **分诊**：Qwen → 智谱 → Groq 70B → Ollama → OpenCode → OpenRouter
- **每日品种解读**：Qwen → 智谱 → Ollama → Groq 70B → OpenCode → OpenRouter
- **一般/重要事件深度分析**：Qwen → 智谱 → Ollama → OpenCode → OpenRouter
- Groq 70B 每天最多 1,000 次；OpenRouter 每天最多 45 次，为 50 次免费额度保留余量。Workers AI 同时保留每天 8,000 Neurons 的代码保护阈值。

用 `CHAIN_TRIAGE` / `CHAIN_ANALYSIS` / `CHAIN_ANALYSIS_IMPORTANT` / `CHAIN_BRIEF` 可以改顺序，用 `OLLAMA_MODEL` 等变量可以换模型，用 `<提供商>_DAILY_REQUESTS` 可以改每日上限（如 `OLLAMA_DAILY_REQUESTS = "500"`）。

**容错机制：**
- 免费模型不支持 Claude 那种强制工具调用，所以统一做法是：在提示里附 JSON Schema，从回复里提取 JSON（会去掉 `<think>` 思考块和代码块标记），再按 schema 清洗。能修的类型自动修（例如 `"3"` 修成 3），数组里不合格的元素直接丢掉，缺必填字段就判为不合格。不合格时会把错误发回给模型重试一次，还不行就换下一家。
- 冷却时间：限流 10 分钟（有 Retry-After 时按它来）；服务故障 5 分钟；key 无效或欠费 6 小时，避免反复撞墙。
- 每次调用都记录到 `api_usage`，包括是哪家哪个模型、token 数、失败次数和花费。每条分析结果都标明是哪个模型生成的。
- 所有模型都失败时抛错，交给队列稍后重试。

**费用**：只配免费 key 时，Claude 费用是 $0，只付 Workers 平台的 $5/月。配了 Anthropic key 后，重要事件优先用 Sonnet，每天花费不超过 `DAILY_BUDGET_USD`（默认 $2），超过后自动只用免费模型。

**质量提示**：免费模型做复杂的结构化分析，稳定性不如 Sonnet。分析结果都标了来源模型；可以用“模型校准”页的方向命中率，按模型对比一段时间后再调顺序。

**其他省调用量的机制**（对免费额度同样重要）：
- 重新分析门槛：已分析的事件，新增报道至少达到 max(3 篇, 30%)，或距上次分析超过 6 小时且有新报道，才会重新分析。
- 每次分析最多带 15 篇报道、每篇 2000 字符（`MAX_SOURCES` / `MAX_SOURCE_CHARS`）。
- 分诊粗分低于 `MIN_TRIAGE_SEVERITY` 的事件不做深度分析。

**D1 用量**：行情只写新 K 线，大约每天 600 行。之前每小时重写 5 天数据，每天约 3.7 万行。文章正文 30 天后清除，只保留标题、摘要和链接（`CONTENT_RETENTION_DAYS`），既控制数据库体积，也减少保存他人全文的版权风险。

## 合规提示

- 网站只做事件影响分析和行情归因，不提供做多/做空信号、目标价、止损或仓位建议。提示词里明确禁止这些内容，页面上的分析也都标注了“不构成投资建议”。
- 如果以后想加交易信号：在美国，向公众提供期货交易建议可能需要在 CFTC/NFA 注册为商品交易顾问（CTA），有豁免情形；在中国属于需要持牌的期货投资咨询业务。上线前请先咨询专业意见。
- 数据源只用 RSS 和 GDELT。NewsAPI.org 等免费档不允许生产使用，所以没有接入。
- 如果要面向中国大陆公众开放，涉及互联网新闻信息服务许可和生成式 AI 服务备案等要求，需要另外评估。个人自用的研究工具一般不涉及这些。我不是律师，正式对外开放前请咨询专业意见。

## 部署

```bash
npm install
npx wrangler login

npx wrangler d1 create news-radar          # 把输出的 database_id 填进 wrangler.toml
npm run db:init                            # 建表
npx wrangler vectorize create news-radar-articles --dimensions=1024 --metric=cosine
npx wrangler queues create news-radar-jobs

./scripts/set-secrets.sh                   # 逐个录入密钥（输入不回显、不落盘，回车跳过）

npm run deploy

# 首次初始化（按顺序）
A="Authorization: Bearer $ADMIN_TOKEN"; W=https://<你的worker>
curl -X POST $W/api/admin/llm/test -H "$A"        # 逐家测试模型 key 和模型名
curl -X POST $W/api/admin/init     -H "$A"        # 写入默认信源
curl -X POST $W/api/admin/curves   -H "$A"        # 识别主力合约、期限结构，回填主力小时线，生成快照
curl -X POST $W/api/admin/ingest   -H "$A"        # 采集一次新闻
curl -X POST $W/api/admin/brief/brent -H "$A"     # 试生成一个品种的 AI 解读（之后每天自动生成）
```

**从旧版本升级**：按顺序执行没跑过的迁移脚本（0002 → 0005），命令是 `npx wrangler d1 execute news-radar --remote --file=<文件>`。v0.4 只需跑 `0005_futures.sql`。这个脚本会重建 `prices` 表，并将所有旧行情保留为连续合约 `cont`。之后部署，再执行一次上面的 `/api/admin/curves`。旧事件的资产代码是旧品种表里的，下次重新分析后会更新。

**定时任务（UTC）**：每 15 分钟采集新闻、调度分析，并分 4 组抓主力小时线；每小时校准事件、刷新品种快照；22 点分 4 组更新期限结构；23 点生成 12 个品种的解读；每天 4 点清理旧正文。

**已知不确定点**：Yahoo 单个合约的代码格式（`CLZ26.NYM`、`GCZ26.CMX`、`ZSF27.CBT`、`ESZ26.CME`）是按惯例拼的，这里没法实际请求验证。如果 `/api/admin/curves` 返回“没有找到在交易的合约”，就改 `src/instruments.js` 里对应品种的 `exchange` 字段。在那之前，行情会用连续合约兜底，只是没有期限结构。

之后 cron 每 15 分钟会自动运行。第一批深度分析大约在 15–30 分钟后出现。没有后端时打开页面加 `?demo=1`，会显示演示数据。

## 调参

`wrangler.toml` 的 `[vars]`：

- `CLUSTER_THRESHOLD`（默认 0.78）：不相关的新闻被合并在一起就调高，同一件事被拆成多个事件就调低。上线后先观察一两天再调。
- `MIN_TRIAGE_SEVERITY` / `MAX_ANALYSES_PER_RUN`：控制 Claude 费用的两个主要旋钮。
- 信源存在 `sources` 表里，可以直接用 SQL 增删或禁用（`enabled = 0`）。`src/sources.js` 里的 RSS 地址上线前请逐个确认仍然有效，`/api/sources` 会显示抓取错误。
